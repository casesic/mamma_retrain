# 真实骑行图片：原模型与 500 步模型人工对照

这是一份**待您评审**的对照材料，不是有真值的测试集。两套模型在同一张原图、同一个人物 mask 和同一裁剪上预测；页面直接标明“原模型”和“500 步模型”。请分别判断点位与可见性。交付时没有任何人工评分，因此不能据此说真实图片的精度已经提升。

## 打开页面

在终端运行：

```bash
cd /mnt/data1/yy/home/yy/Projects/mamma_retrain
/mnt/data1/yy/home/yy/Repos/mamma/.venv/bin/python scripts/real_review_server.py --port 18868
```

然后在**同一台机器**的浏览器打开 `http://127.0.0.1:18868/`。服务只监听本机，只允许读取本轮选中的原图、mask 和评审数据；原图仍在只读的 `riding-data` 目录。若 18868 已被占用，可给 `--port` 换一个空端口，浏览器地址也同步修改。退出服务按 Ctrl+C。

页面上方按源帧切换时，**同一帧的 cam2 和 cam4 并排显示完整 ERP**。每路先用自己的“人物”下拉框选一个目标；整图**只画所选人物**的 512 点和一个黄框，避免其他人的点、框叠在一起。在“双机画面显示”选择原模型或 500 步模型，也可切到仅原图。两张整图可以分别拖动平移、滚轮缩放，“双机画面复位”回到完整 ERP。可独立勾选模型判可见的实心点、模型判遮挡的空心点、原图／物理有效域外的灰叉；三类默认全显示。

每边的检测人物编号**不是跨机身份**，页面不会自动断言两边选中的是同一个人。两边手动选好要比较的人后，把鼠标移到一个点上，两张整图和下方两模型细看图会同步突出**相同模板点编号**；每路仍按自己的预测显示该点的实心、空心或灰叉，并在各自下方列出可见概率。这是点序联动，不是跨相机自动身份匹配。选中任一机位的人物后，下方仍有较大的三栏局部细看区和该目标的评审表；三个局部窗口同步平移和放大。mask 开关在整图及细看区只显示当前选中人物的 mask。灰色叉号表示预测在原图或该相机物理有效域外，不表示关键点真值。5 个需要在 ERP 下边界补黑的目标在人物信息栏明确标记补齐像素数。

每个人物的“点位贴合程度”和“可见性／遮挡判断”分别选择原模型更好、相近、500 步模型更好或无法判断；也可标记输入 mask 问题并备注。**初始两项都为“尚未评审”**。选项会保存到当前浏览器草稿，请定期点击“导出评审 JSON”另存文件。导入时会核对评审集、319 个目标的顺序及两份模型的文件身份，错配文件会拒绝。此前页面导出的 A/B 评审文件仍可导入，原有选择会按保存的模型映射正确显示；新页面不再隐藏模型身份。汇总只数您实际填写的判断，未评审、无法判断和 mask 问题分别保留。

## 本轮固定输入和处理

[冻结选样](../outputs/experiments/real_riding_manual_review_20261024/selection.json)在查看新模型结果前按各组时间轴 20 个等分区间选中点冻结：data3、data4 各 20 对同步图，共 40 对、80 张原始 5760×2880 ERP PNG。两机文件名成对，没有重新从有损视频取帧。data3 使用 20260320 有效域，data4 使用 20260311 有效域。可先看[原图接触表](../outputs/experiments/real_riding_manual_review_20261024/selection_contact_sheet.jpg)；它能帮助定位远近尺度、多人和边缘画面，但不替代逐张人工确认遮挡。

使用既有 `yolo26s-seg_fp32.engine` 做了一次分割，输入长边缩到 1600，`imgsz=(640,1280)`，person 类、检测阈值 0.05、最多 50 个原始候选；本轮纳入条件固定为分数 ≥0.15、框面积不超过整幅 ERP 的 10%、有非退化且落在该相机物理有效域内的 mask。不只保留最大人物，也没有按任一 MAMMA 预测挑人。80 张图均有至少一个纳入目标；[检测与逐人 mask 清单](../outputs/experiments/real_riding_manual_review_20261024/targets.json)记录 319 个目标（data3 265、data4 54），另有 345 个低分候选和 38 个过大框按固定规则拒绝。少量分割质量仍需您在页面标“输入 mask 有问题”，不能算作某套 MAMMA 独有错误。

最初严格源支持预检把 5 个有前景的检测目标挡住。逐一复核发现它们都只是在**下边界**缺少裁剪与滤波所需像素，水平跨度没有超过一个 ERP 周期；这不等于确认其分割质量或人体点可从画面判断：

| 目标 | 下方补黑 |
| --- | ---: |
| `data4_cam4_00518_p01` | 158 px |
| `data4_cam4_00884_p01` | 895 px |
| `data4_cam4_03906_p01` | 38 px |
| `data4_cam4_04708_p00` | 185 px |
| `data4_cam4_05076_p02` | 1198 px |

真实完整 ERP 输入现在显式采用垂直黑色原始像素及零 mask 补齐，水平方向仍周期采样；先补完整采样区再做原有滤波和仿射，不移动 mask 框，也不夹住图外预测。合成包的完整源支持检查仍严格拒绝越界。[最终准备清单](../outputs/experiments/real_riding_manual_review_20261024/targets_ready.json)为 319 个、零个裁剪拒绝。原先 314 个推理结果复用，仅给新增 5 个各补跑两套权重。

## 两套模型与文件

原模型严格加载 [tensor_state.pt](../outputs/experiments/mamma_original_baseline_pilot_20261015/tensor_state.pt)；微调模型严格读取 [第 500 步恢复 checkpoint](../outputs/experiments/city_full_first_finetune_20261024/train_resume_500/checkpoint_update_000500.pt)中的 `model_state`，实际合同为 `mamma_regular_resume_v5`、`global_update=500`、282 个模型键。两者都用本项目当前 512 点 MAMMA 配置、PyTorch FP32、eval 和 inference_mode；未用旧 TensorRT 部署 engine。顺序推理使用物理 GPU1，UUID `GPU-6f046d56-acbe-d49b-774a-9d463e768cac`，在进程内映射为 `cuda:0`。未训练或修改现有部署权重。

精确输出分别在 [原模型 NPZ](../outputs/experiments/real_riding_manual_review_20261024/predictions_original.npz)和[500 步 NPZ](../outputs/experiments/real_riding_manual_review_20261024/predictions_finetuned_500.npz)：同顺序的 319 个 target、每个 512 个网络原始归一化 XY、还原后的完整 ERP XY、visibility logits 和 sigmoid 概率，并带输入仿射与本轮训练使用的有序顶点表。原始 XY 曾在首次保存时遗漏，随后用同一权重与固定输入补录；逐目标确认重新还原的 ERP 坐标和 logits 与已有结果一致，没有替换页面预测。[review_data.json](../outputs/experiments/real_riding_manual_review_20261024/review_data.json)与[mapping.json](../outputs/experiments/real_riding_manual_review_20261024/mapping.json)的数据内容未改；页面读取映射后直接显示真实模型名称。物理有效域和原图外标记是预测位置的状态，**不是**人工点位或可见性 GT。

两模型每个目标的 RGB 张量、mask 张量、仿射与派生框均逐数组形成相同的输入指纹，并在第二次推理前检查；319 个均通过。全部输出有限，页面数组与 NPZ 按模型映射逐目标核对一致。补黑的 5 个真实输入均为 `(3,512,384)` RGB 和 `(1,512,384)` mask。小型数值检查确认内部目标与修改前输入完全相同；接缝加上边界补黑、非接缝和坐标逆变换通过。合成包仍拒绝同类越界，现行 11 项 CPU 测试通过。浏览器实测了同帧 cam2/cam4 整图、每路只绘制所选人物、切换人物不改变另一机位选择、同编号点双机联动、模型切换和页面无异常；此前还验证了三类点开关、两机独立缩放与拖动、复位及跨数据组切换。ERP 画布显示宽高比在桌面和窄窗口均为 2:1。[当前双机所选人物与点联动截图](../outputs/experiments/real_riding_manual_review_20261024/review_selected_person_linked_point.png)保留空白评分状态。旧[边界案例截图](../outputs/experiments/real_riding_manual_review_20261024/review_border.png)仅展示裁剪与评审入口，不构成该目标的正确性判定。

[diagnostics.json](../outputs/experiments/real_riding_manual_review_20261024/diagnostics.json)里的坐标差与可见性翻转仅表示**两套模型意见不同**，不是坐标误差、正确率或遮挡召回。真实图片没有人工 512 点及 visibility GT；本轮不运行 GT 评价，也不代您填写任何评审。待您导出评审 JSON 后，才能根据实际人工判断讨论是否有帮助。

## 追加的类均衡模型（2026-10-24）

[类均衡 500 步实验](VISIBILITY_CLASS_MEAN_20261024.md)只改变 visibility 损失的逐样本归约。它在同一冻结 80 张原图、319 个人物和已存 mask 上补做了模型推理；没有重新检测、重选目标或改写上面两份旧预测。[新预测 NPZ](../outputs/experiments/city_full_visibility_class_mean_20261024/predictions_real_class_mean_500.npz)保存有序 512 点的网络原始坐标、完整 ERP 坐标、visibility logits/概率、输入仿射与模板点序。人物顺序和旧预测完全一致，输入仿射按旧文件的 float32 存储精度相同；新预测有限值，周期坐标还原检查通过。

打开上面的**同一个页面**，在“双机画面显示”可选“原模型”“普通 BCE 500 步”或“类均衡 500 步”。同帧 cam2/cam4 仍各选一个人物、保持完整 2:1 ERP、同编号点联动和三类点显示开关。下方“人工比较”可以在原有的“原模型 vs 普通 BCE”和新的“普通 BCE vs 类均衡”之间切换；两组草稿有不同的评审集 ID 和模型身份，导出文件互不混用，新组初始全部未评审。现有浏览器中的旧评分不会自动迁入新组。**正在运行的旧页面服务不会自行加载新代码；请在方便时重启该评审服务。**

新模型在 319 个真实目标上有 80,677 个点判可见，普通 BCE 有 79,594 个，两者有 1,209 个点的 0.5 阈值判断不同。它们不是遮挡召回或真实精度。独立临时浏览器实测页面可载入 319 个目标、切换类均衡双机叠加、将新评审导出再导入、切回旧比较而不改变旧评分；测试使用全新临时浏览器资料，没有填写用户的实际评审。

## 追加的 30% 遮挡取样模型（2026-10-25）

## 追加的合并遮挡数据模型（2026-10-25）

[合并数据 30% 实验](CITY_MERGED_OCCLUSION_30PCT_20261025.md)从原始权重重新训练，给固定 319 个 target 增加第五套预测。“双机画面显示”可选“新增遮挡数据＋30% 取样”。下方默认打开独立的“原模型 vs 新增遮挡数据 30%”人工比较；“旧数据 30% vs 新增遮挡数据 30%”仍可选，用于分析新增数据的额外作用。两个新增评审组有各自的评审集 ID，初始均为空，不迁移之前的评分；导入时核对当前比较的模型身份。

原模型在这 319 个目标上预测 31,357 个可见点，本轮模型预测 89,979 个；旧数据 30% 模型预测 90,070 个。真实图片没有人工 512 点真值，可见点数量不能代表判断正确率。临时独立 Chrome 已载入新预测和双机图片，实际检查主对照与附加对照的空白状态、评分保存、导出再导入、错组导入拒绝和旧组隔离；测试资料未进入用户浏览器。本轮没有代用户填写评分。正在运行的旧评审服务不会自动加载新页面，用户方便时需重启自己的服务。

## 追加的合并数据全量一遍模型（2026-10-25）

[全量一遍实验](CITY_MERGED_FULL_EPOCH_20261025.md)将 3245 条有监督训练观察各用一次，给相同的 319 个真实目标增加第六套预测。现在页面默认比较“原模型 vs 合并数据全量 1 遍”；也可选“合并数据 500 步 vs 全量 1 遍”。两个新组分别保存评分，旧组和旧评分保留。双机仍各选一个人、保持完整 ERP 的 2:1 比例和同编号点联动，可切换可见、遮挡及图外点。
