# 真实双机合图：原模型 0.5 与全量一遍模型 0.85

这次把固定的 40 对真实双机 ERP 图片送入**现有演示合图链**，让人直接比较完整合图。当前看图页只显示原模型阈值 0.5 与全量一遍微调模型阈值 0.85。原模型来自[原始 tensor_state](../outputs/experiments/mamma_original_baseline_pilot_20261015/tensor_state.pt)，全量一遍模型来自[第 812 步 checkpoint](../outputs/experiments/city_merged_one_epoch_20261025/train_full/checkpoint_update_000812.pt)。图片、人物 mask 和两套模型预测都沿用[已冻结的真实评审集](REAL_RIDING_MANUAL_REVIEW_20261024.md)；没有重新检测或推理。此前生成的微调模型阈值 0.5 图片留在清单中，不再参与当前主要画面对照。

## 打开看图页

在 `mamma_retrain` 目录执行：

```bash
/mnt/data1/yy/home/yy/Repos/mamma/.venv/bin/python scripts/real_stitch_review_server.py \
  --host 127.0.0.1 --port 18872
```

然后用本机浏览器打开 `http://127.0.0.1:18872/`。端口被占用时换一个本机空闲端口。页面能切换 40 对帧，两栏同步放大、缩小和平移；“放大人物”定位到当前配对目标。切帧先读取较轻的 1440×720 预览，放大超过 2.5 倍时自动读取 5760×2880 原图；“打开无损合图”也始终通向原分辨率 PNG。页面下方还能打开同帧 cam2/cam4 原图。人工逐帧评分初始全部为空，可导出／导入独立评审 JSON。它与旧的点位评审及 0.5 阈值评分互不覆盖。**已在运行的旧服务需要由您稍后重启，才会提供快速预览路由和两栏页面**；在重启前，页面会自动改用完整图片，仍可继续查看。

[合图清单](../outputs/experiments/real_riding_stitch_threshold085_20261025/index.json)列出全部图片、每组实际人物配对、点对、变形准入和拒绝原因。图像位于同目录 `frames/data3_<源帧>/` 和 `frames/data4_<源帧>/`。例如 [data3/01145 原模型](../outputs/experiments/real_riding_stitch_threshold085_20261025/frames/data3_01145/original_050.png) 与 [同帧全量一遍 0.85](../outputs/experiments/real_riding_stitch_threshold085_20261025/frames/data3_01145/full_epoch_085.png) 展示了阈值改变后配对／变形被拒的情况。

## 实际合图链与结果

按用户选择，本轮沿用 `riding-data` 交付演示视频的链：`mamma-deploy` 的当前帧 D 人物配对 → `riding-data` 的 cam4→cam2 方向与网格准入检查 → 局部位移网格变形 → E 归属与有效域硬覆盖。cam2 是参考图；配对或变形不成立时保留该链的基础拼接。`mamma-deploy` 单独只做到点对。本链的局部网格来自演示实现，**不是 canonical CPW，也不是公司的最终合图实现**。适配脚本只读调用原模块，没有复制或修改 `/home/yy/Repos`。data3 使用 20260320 有效域，data4 使用 20260311 有效域。

| 方案 | 40 对中的实际变形 | 配对后被网格门槛拒绝 | 无配对 |
| --- | ---: | ---: | ---: |
| 原模型，0.5 | 37 | 0 | 3 |
| 全量一遍，0.85 | 35 | 3 | 2 |

两组分别使用同一批 RGB、mask、标定及合图参数，重新按各自的坐标和可见概率做人物配对、双侧点筛选及变形准入；没有强行复用原模型的人物对应关系，也没有把两机相同的 `raw_index` 当作同一人。40 对中 data3/data4 各 20 对；当前主要对照的 80 张合图均为 5760×2880，无配对或被拒的帧也在页面上。首帧 data3/01145 中，原模型配到 cam2 的 p03，而 0.85 模型配到 p02，后者被 `mesh_fold_attenuation` 拒绝，因而两个画面走了不同的拼接路径。data3/01488 被 `tail_fit_residual` 拒绝，data3/01529 也被 `mesh_fold_attenuation` 拒绝。点对总数或准入率不是画面质量指标；查看原图时仍可见演示链自身的接缝和背景断裂，不能把这些归因于 MAMMA 一项。

用户看过当前真实演示合图后的整体判断是：**两组画面效果差不多，0.85 方案主要是可用点更多**。这是一条总体人工观察，不是给 40 帧逐一填写的评分，也不是有真值的准确率。保存记录支持“可用点更多”的具体含义：在两组**都成功变形的同一 35 帧**里，原模型用于变形的点对合计 2,474，0.85 方案合计 3,665；不同帧的配对人物可能不同，因此不能仅凭合计数判断点对质量。提高阈值本身只会筛掉同一模型的点，不会凭空增加点；这里的更多点是**新模型与原模型**比较后的合图结果。0.85 方案仍有上述三次网格拒绝，不能把“更多点”解释为“所有帧都更好”。

生成 120 张图用时 275.448 秒，直接读取保存预测，未调用 GPU、模型、检测器、训练或 Blender。复现脚本为 [real_riding_stitch_compare.py](../scripts/real_riding_stitch_compare.py)；它拒绝覆盖已有输出目录。默认参数针对本机现有只读外部模块，换机器时需显式指定脚本帮助中列出的模块目录和原始数据路径仍可访问。原始合图约 1.95 GiB，未复制原始 ERP 数据库。为缩短逐帧浏览，另从合图一次性缩小得到 120 张预览，合计约 181 MiB；每对三张预览平均约 4.5 MiB，原图平均约 50 MiB，原始合图像素未改变。

验收核对了 40 对的相机／标定归属、三组保存记录及全部原图与预览的尺寸。独立临时 Chrome 曾实际载入 40 帧索引与首帧预览，确认页面先请求预览；两栏收敛后又做了语法和请求路径检查。原点位评审页也已确认默认显示 0.85 及两路原图。页面评审的保存、导入及错组拒绝做了隔离逻辑检查，未代用户逐帧评分。用户已有上述总体画面判断；现有服务未重启。

统一合成验证集的 814 条观察、111,917 个可见标签与 21,756 个遮挡标签上，保存概率按 `p≥0.85` 重算得可见召回 **91.33%**、遮挡召回 **94.76%**；坐标点均误差仍为 **2.5242 px**。[完整一遍报告](CITY_MERGED_FULL_EPOCH_20261025.md)保留历史阈值结果。真实固定的 319 个目标中，微调模型按 0.85 判断有 69,868 个可见点；这是输出数量，不是对错。0.85 是看过这份验证集后选定的阈值，不是独立测试。真实 40 对没有人工 512 点真值，用户的画面判断是目前最直接的实际反馈，但还不能据此推断真实点位准确率或连续视频稳定性。
